# 2026-08-02 工作日志

## SztuCode 评测体系搭建

用户询问如何用行业标准流程评测自研 coding agent 项目。完成了以下工作：

### 1. 项目分析
- SztuCode 是一个从零构建的本地 AI Coding Agent（mini Claude Code）
- 双进程架构：daemon (TCP 127.0.0.1:7437) + CLI/TUI/Desktop 多客户端
- 8 个开发阶段（S0-S7），核心模块：Agent Loop、工具系统、权限管理、上下文压缩、Session、MCP、Subagent、Trace
- 已有 55 个单元测试 + 5 个集成测试，但无任何能力评测代码

### 2. 评测方案设计
设计了三层评测体系：
- **Layer 1: 标准基准评测** — SWE-bench Lite (300 tasks) / SWE-bench Verified (500 tasks) / HumanEval+MBPP
- **Layer 2: 轨迹质量评测** — 路径效率、工具纪律、爆炸半径、失败诚实度
- **Layer 3: 工程维度评测** — Loop 鲁棒性、上下文治理、权限安全、成本效率

### 3. 代码交付
创建了 `eval/` 目录结构：
- `eval/swebench/adapter.py` — SWE-bench Harness 适配器（将 SztuCode agent.run 包装成 SWE-bench 要求的 JSONL 接口）
- `eval/trajectory/analyzer.py` — 轨迹质量分析器（从 events.jsonl 提取路径效率、工具纪律、成本等指标）
- `eval/reports/generator.py` — 评测报告生成器（聚合所有维度生成 Markdown 报告）
- `docs/evaluation_guide.md` — 完整评测实施指南（含 SWE-bench 接入步骤、代码示例、报告模板、推荐路径）

### 4. 关键技术决策
- SWE-bench 的接入契约：只需实现"输入 issue + 仓库路径，输出 unified diff"的函数
- 利用 SztuCode 已有的三层 Trace 系统（IPC/EventBus/LLM）作为轨迹分析的数据源
- 评测时使用 AUTO 权限模式（自动批准所有操作）
- 推荐 Phase 1 从 SWE-bench Lite 10 个实例起步验证流程
