# 深度技术文章写作指南

> 来源标准：Google Developer Documentation Style Guide + 技术写作最佳实践

## Goal

帮助创作有深度、有洞察、有实践价值的技术文章——不是文档翻译，而是经验沉淀。

## Pre-Writing Questions

1. **目标读者**：初级/中级/高级？前端/后端/全栈/DevOps？
2. **核心问题**：读完这篇文章，读者能解决什么问题？
3. **独特价值**：跟官方文档/其他文章比，你的文章多了什么？（踩坑经验？性能数据？场景对比？）
4. **前置知识**：读者需要提前了解什么？
5. **技术栈版本**：涉及哪些工具/框架？版本号？

## 文章结构模板

### 版本 1：原理解析型

**适用场景**：解释某技术的工作原理（React RSC / Rust 所有权 / TCP 三次握手）

```markdown
# [技术名] 深度解析：[核心价值]

## TL;DR
## 背景：为什么需要关注 [技术名]？（痛点/趋势）
## 核心概念
### 概念 1：[用类比解释]
### 概念 2：[用图表辅助]
## 实战：代码验证
### 最简示例
### 进阶用法
## 原理深挖：它是怎么实现的？
## 踩坑记录 / 常见问题
## 性能/对比（如适用）
## 总结：什么场景该用/不该用
## 延伸阅读
```

→ 参见 `examples/article-deep-dive.md`

### 版本 2：实战经验型

**适用场景**：分享解决某个具体问题的过程（性能优化/Bug排查/架构升级）

```markdown
# [动作]：如何将 [指标] 从 [X] 优化到 [Y]

## TL;DR
## 问题发现：发生了什么？（现象+数据）
## 排查过程：如何定位？（工具+方法+走过的弯路）
## 根因分析：为什么会这样？
## 解决方案：怎么修的？（代码diff+原理）
## 效果验证：修完后数据（前后对比表格）
## 总结：可复用的方法论
```

→ 参见 `examples/article-experience.md`

### 版本 3：技术选型/对比型

**适用场景**：对比多个技术方案（ORM 选型 / 框架对比 / 数据库选型）

```markdown
# [场景] 技术选型：[A] vs [B] vs [C]

## TL;DR：推荐结论（先给答案）
## 评测维度与权重
## 候选方案逐个分析
### 方案 A：[优势] + [劣势] + [最佳场景]
### 方案 B：...
## 对比矩阵（表格）
## 实测数据（Benchmark）
## 选择建议：什么场景用什么
```

→ 参见 `examples/article-comparison.md`

## 代码规范

```
✅ 每段代码标注语言：```javascript / ```python / ```bash
✅ 关键行加注释说明
✅ 可运行的完整示例（不是片段）
✅ 标注依赖版本：Node.js 20+, Python 3.11+
✅ 分步骤展示：先最简 → 再增量添加功能
❌ 不要贴超过 50 行的大段代码（拆分+注释）
❌ 不要假设读者能自行脑补省略部分
```

## 图表策略

| 图表类型 | 适用场景 | 工具建议 |
|---------|---------|---------| 
| 架构图 | 系统组件关系 | Excalidraw / Mermaid |
| 流程图 | 数据/请求流向 | Mermaid flowchart |
| 时序图 | 多组件交互 | Mermaid sequence |
| 对比表格 | 方案选型 | Markdown table |
| 性能图表 | Benchmark 结果 | Chart 截图 |

**原则**：复杂关系必须有图，能用 Mermaid 尽量用（可维护性好）。

## SEO 优化

```
标题：包含核心技术关键词 + 价值描述
  ✅ "React Server Components 深度解析：从原理到实践"
  ❌ "聊聊RSC"

副标题/描述：50-160 字的文章摘要
标签：3-5 个技术关键词
```

## Quality Checklist

- [ ] 标题是否包含技术关键词+价值描述？
- [ ] 代码示例是否可运行、版本已标注？
- [ ] 是否有独到见解（不只是文档翻译）？
- [ ] 结构是否支持快速扫读（标题+粗体+代码块）？
- [ ] 复杂概念是否有类比或图表辅助？
- [ ] 是否说清了适用边界和 trade-off？
