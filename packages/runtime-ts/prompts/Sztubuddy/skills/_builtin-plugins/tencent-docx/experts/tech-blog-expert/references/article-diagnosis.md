# 技术文章诊断指南

> 来源标准：Google Developer Documentation Style Guide + 技术文章五维度评估体系

## Goal

帮助评估现有技术文章质量，识别问题并输出优化方案。

## 技术文章五维度评价标准

| 维度 | 权重 | 评价标准 |
|------|------|---------| 
| **技术准确性** | 30% | 概念无误、代码可运行、版本匹配、引用准确 |
| **结构清晰度** | 25% | 逻辑递进、标题层次分明、可快速扫读 |
| **实用价值** | 20% | 读者能否直接应用？有无可运行示例？ |
| **深度与洞察** | 15% | 是否有独到见解？不只是文档翻译？ |
| **表达质量** | 10% | 语言流畅、图文并茂、阅读体验好 |

## 致命问题清单（发现即扣重分）

- ❌ 代码示例无法运行 / 有语法错误
- ❌ 概念解释错误 / 混淆
- ❌ 版本不标注导致读者踩坑
- ❌ 抄袭他人文章/代码不注明出处

## 诊断流程

```
1. 通读全文，标记第一印象
2. 逐项检查致命问题
3. 五维度逐一评分（1-10）
4. 问题清单（按严重程度排序）
5. 输出优化建议
```

## 诊断报告模板

```markdown
## 技术文章诊断报告

### 综合评分：X/10

### 致命问题检查
- ✅/❌ 代码可运行性
- ✅/❌ 概念准确性
- ✅/❌ 版本标注
- ✅/❌ 引用注明出处

### 五维度评分
| 维度 | 得分 | 分析 |
|------|------|------|

### 问题清单（按严重程度排序）
1. 🔴 [致命问题]
2. 🟡 [改进建议]
3. 🟢 [优化空间]

### 优化建议
#### 结构优化
[建议]
#### 内容补充
[建议]
#### 表达提升
[建议]
```

## 常见诊断问题对照

| 症状 | 可能原因 | 建议 |
|------|---------|------|
| 读者反馈"看不懂" | 缺少前置知识说明/跳步 | 补充背景、添加类比 |
| "代码跑不通" | 版本不匹配/环境缺失 | 标注版本、补完整示例 |
| "没有收获" | 只是文档翻译无洞察 | 增加踩坑经验/对比数据 |
| "太长不想看" | 结构不支持扫读 | 添加TL;DR/层次标题/粗体 |
| "看完不知道怎么用" | 缺乏实战示例 | 补充 Step-by-Step 实战 |

## Quality Checklist

- [ ] 是否逐项检查了致命问题？
- [ ] 是否按五维度逐一评分？
- [ ] 问题是否按严重程度排序？
- [ ] 优化建议是否具体可操作？
