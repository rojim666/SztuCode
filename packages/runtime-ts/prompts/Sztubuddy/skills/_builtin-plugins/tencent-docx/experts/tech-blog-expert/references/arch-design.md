# 架构设计文档写作指南

> 来源标准：C4 Model + arc42 + 技术架构文档最佳实践

## Goal

帮助创作让读者快速理解系统全貌、核心决策及 trade-off 的架构文档。

## Pre-Writing Questions

1. **系统定位**：这个系统解决什么问题？服务谁？
2. **架构重点**：最值得讲的 2-3 个设计决策是什么？
3. **读者需求**：是想了解全貌还是某个具体决策？
4. **非功能需求**：性能/可用性/安全/成本，哪个是核心约束？

## 架构文章结构模板

### 版本 1：系统架构全景

**适用场景**：介绍一个完整系统的架构设计

```markdown
# [系统名] 架构解析

## 一句话描述
## 架构全景图（必须有图）
## 技术栈一览（表格）
## 核心设计决策
### 决策 1: 为什么选 [X] 而不是 [Y]
  - 背景约束
  - 方案对比（表格）
  - 最终选择及理由
  - Trade-off 说明
### 决策 2: ...
## 数据流 / 请求链路
## 关键模块详解
## 可扩展性 / 容灾设计
## 性能指标与瓶颈
## 经验教训 / 踩坑记录
## 适用边界：什么场景适合/不适合
```

→ 参见 `examples/arch-system.md`

### 版本 2：单一决策深度分析

**适用场景**：深度分析某个架构决策（如微服务拆分、数据库选型、缓存策略）

```markdown
# [决策主题]：我们为什么选了 [方案]

## 背景：遇到了什么问题
## 约束条件（必须满足 / 最好满足 / 不重要）
## 候选方案分析
### 方案 A: [简述 + 优劣]
### 方案 B: ...
## 决策矩阵（表格：方案 × 评估维度 × 打分）
## 最终选择及理由
## 实施后的真实数据
## 如果重来会怎么做
```

## 架构图规范

```
必须包含的图（至少一个）：
1. 系统上下文图（C4 Level 1）：系统与外部的关系
2. 容器图（C4 Level 2）：系统内的主要容器/服务
3. 数据流图：核心请求的完整链路

推荐使用 Mermaid 语法（可维护性好）：
- flowchart TD/LR — 架构图/流程图
- sequenceDiagram — 请求链路
- erDiagram — 数据模型
```

## 设计决策记录模板 (ADR)

```markdown
### ADR-001: [决策标题]

- **状态**：已采纳 / 已废弃 / 提议中
- **日期**：YYYY-MM-DD
- **上下文**：[为什么要做这个决策]
- **决策**：[选了什么方案]
- **理由**：[为什么选它]
- **后果**：[好的/坏的/需要注意的]
```

## Quality Checklist

- [ ] 是否有架构全景图？
- [ ] 核心决策是否说清了"为什么"而不只是"是什么"？
- [ ] Trade-off 是否诚实说明？
- [ ] 是否有实际数据支撑（而非理论分析）？
- [ ] 适用边界是否明确？
