## 范例：Node.js ORM 选型（仿真节选）

%% 标题策略：明确对比对象 + 年份（时效性）
%% 开头先给结论——忙的读者只看这一段

### 标题
> Node.js ORM 选型指南（2026）：Prisma vs Drizzle vs TypeORM

### TL;DR

%% 先给答案，再展开分析——技术选型文章的黄金法则

> - **追求开发效率 + 团队新手多** → Prisma
> - **追求性能 + SQL 掌控力** → Drizzle  
> - **已有 TypeORM 项目** → 继续用，迁移成本 > 收益

### 评测维度段落

%% 策略：先定义"怎么评"，再评——让读者认可你的评测框架

```markdown
## 评测维度与权重

| 维度 | 权重 | 评价标准 |
|------|------|---------|
| 类型安全 | 25% | Schema→TypeScript 类型推导的完整度 |
| 查询性能 | 25% | 相同查询场景下的执行耗时（Benchmark） |
| 开发体验(DX) | 20% | 学习曲线、文档质量、迁移工具 |
| 生态成熟度 | 15% | GitHub stars、npm 周下载量、Issue 响应 |
| 灵活性 | 15% | 复杂查询/Raw SQL/自定义扩展能力 |
```

### Benchmark 段落

%% 策略：用实际测试数据说话，不用"感觉更快"
%% 标注测试环境（可复现性）

```markdown
## 实测 Benchmark

测试环境：Node.js 22, PostgreSQL 16, M2 Mac, 10万条数据

| 操作 | Prisma | Drizzle | TypeORM |
|------|--------|---------|---------|
| 单条查询 | 1.2ms | 0.8ms | 1.5ms |
| 批量插入(1000条) | 45ms | 28ms | 62ms |
| 复杂 JOIN | 8.5ms | 3.2ms | 12ms |
| N+1 查询 | 自动优化 | 需手动 | 需手动 |

> Drizzle 的查询性能领先 30-60%，因为它生成的 SQL 更接近手写 SQL。
> Prisma 在 N+1 问题上有内置优化（`relationJoins`），开发体验更友好。
```

### 选择建议段落

%% 策略：按场景给建议——不是说"X最好"，而是"什么场景用什么"

```markdown
## 选择建议

| 你的情况 | 推荐 | 理由 |
|---------|------|------|
| 新项目 + 团队 TS 经验少 | Prisma | 学习曲线最低，文档最好 |
| 性能敏感 + 熟悉 SQL | Drizzle | 性能最优，SQL 掌控力强 |
| 已有 TypeORM 项目 | 继续用 | 迁移成本 > 收益 |
| 需要支持多数据库 | Prisma/TypeORM | Drizzle 的非 PG 支持较新 |
```
