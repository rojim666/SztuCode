# Deep Research Engine 参数字典

> 本文档是 `deep-research/engine.md` 的**配套参数文档**，回答 Expert 作者的两个问题：
> 1. 本引擎**可以通过哪些旋钮控制**？（§二 参数清单）
> 2. 我的场景**该传什么值**？（§三 场景模板 / §四 反模式）
>
> **使用方式**：Expert 在自己的 SKILL.md 里，在需要调用本引擎的 Phase 中**显式声明参数**（见 §三 引用范式）。引擎协议本身不含参数值，只负责按传入参数执行状态机。

## 二、参数清单

### 2.1 完整参数总览

| 参数 | 类型 | 必填 | 默认值 | 一句话语义 |
| --- | --- | --- | --- | --- |
| `topic` | string | ✅ | — | 研究主题（一句话描述） |
| `tools` | list | ✅ | — | 本次可用的检索工具名清单 |
| `scope` | enum | ❌ | `"web"` | 检索范围策略 |
| `max_loops` | int | ❌ | `2` | 最大循环次数 |
| `min_facts_required` | int | ❌ | `5` | Reflect Q1 的事实数阈值 |
| `gap_check_strict` | enum | ❌ | `"relaxed"` | Reflect 严格度 |
| `search_dimensions` | list | ❌ | `["事实", "背景"]` | Reflect Q2 的必搜维度清单 |
| `tier_priority` | list | ❌ | `[]` | Tier 1 源的域名/路径优先级 |
| `snapshot_path` | string | ❌ | `output/research/{topic}_research.md` | 快照落盘路径 |

### 2.2 每个参数详解

#### `topic` — 研究主题
- **作用**：进入 Step ① Decompose 时的输入，引擎据此拆解子问题
- **写法建议**：一句话，包含「主体 + 范围 + 角度」（如 "AI Agent 行业 2025 年市场规模"）
- **坏例**：`"AI"`（太宽）、`"AI Agent 行业市场规模趋势预测前景展望全景研究"`（太长，拆解混乱）

#### `tools` — 可用检索工具
- **作用**：告知引擎"在 Step ② Search 中可以调用哪些工具"
- **取值**：调用方定义的工具名字符串列表，如 `["web_search", "read_file"]`
- **关键约定**：**引擎本身不绑定具体工具名**，由调用方注入。这样做的好处：
  - 未来换工具（如 `web_search` → `tavily_search`）不动引擎协议
  - 不同 Expert 可以有不同工具权限
- **空列表视为违约**：至少传 1 个工具

#### `scope` — 检索范围策略
- **作用**：引导 Decompose 和 Search 的"方向感"
- **取值**：
  - `"web"` → 广度优先。优先调用网络检索工具，子问题偏通用
  - `"local_knowledge"` → 深度优先。优先调用本地知识库工具，子问题偏领域
  - `"hybrid"` → 混合。先查本地补权威，再查网络补时效
- **本参数不等于工具列表**：`scope=local_knowledge` 仍可传 `tools=["web_search"]`，只是子问题拆解方向偏本地

#### `max_loops` — 最大循环次数
- **作用**：硬上限，防止无限循环
- **取值范围**：1–5
- **选值指南**：
  - `1` → 仅一次收集，不做缺口回补（轻任务）
  - `2` → 一次初搜 + 一次缺口回补（大多数场景）
  - `3` → 允许两次回补（高质量要求 / 领域专家）
  - `≥4` → 仅用于长文档且时间/成本不敏感场景

#### `min_facts_required` — 事实数阈值（Reflect Q1）
- **作用**：Reflect Q1 判断"事实数量是否达标"
- **取值指南**：
  - 短文档（≤1500 字）：3–5
  - 中长文档（5000 字左右）：5–10
  - 长文档（≥8000 字）：10–15
- **注意**：是 Extract 后的**结构化事实数**，不是搜索结果条数

#### `gap_check_strict` — Reflect 严格度
- **作用**：控制 Reflect 6 问的通过门槛
- **取值**：
  - `"relaxed"`：Q1–Q4 必须通过，Q5（冲突处理）和 Q6（生成预演）可容忍
  - `"strict"`：6 项全部必须通过，任一不过即 CONTINUE

#### `search_dimensions` — 必搜维度清单（Reflect Q2）
- **作用**：Reflect Q2 判断"每个维度是否都有事实覆盖"
- **取值**：字符串列表，维度名由调用方根据文档类型定义
- **常见维度**：`["数据", "趋势", "案例"]` / `["法条", "风险", "判例"]` / `["背景", "现状", "对策"]`
- **数量建议**：2–4 个（太多会让 Reflect Q2 难以全部通过）

#### `tier_priority` — 权威源优先级
- **作用**：在 Extract 阶段判定 Tier 1 时使用
- **取值**：字符串列表，可以是域名（`"gov.cn"`）、关键词（`"白皮书"`）或文件路径前缀
- **匹配方式**：Extract 时如果来源命中任一 `tier_priority` 元素，则优先标为 Tier 1
- **留空**：引擎按内置规则判定 Tier（政府/标准/学术 → T1；白皮书/专业媒体 → T2；其他 → T3）

#### `snapshot_path` — 快照落盘路径
- **作用**：Step ⑥ Snapshot 的输出文件路径
- **默认值**：`output/research/{topic}_research.md`（变量 `{topic}` 由引擎展开）
- **覆盖场景**：Expert 希望把研究快照和最终稿放同一任务目录时，可改为 `output/{task_id}/research.md`
