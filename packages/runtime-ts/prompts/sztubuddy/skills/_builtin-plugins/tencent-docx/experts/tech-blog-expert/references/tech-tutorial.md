# 技术教程写作指南

> 来源标准：认知负荷理论(CLT) + 教学设计(Instructional Design) + Developer Experience

## Goal

帮助创作让读者"从零到能动手"的技术教程——每一步都能验证，每一步都有成就感。

## Pre-Writing Questions

1. **读者起点**：学完这个教程，读者的技术水平从哪到哪？
2. **完成标准**：教程结束时，读者能独立完成什么？
3. **时间预期**：完整跟完需要多少时间？
4. **环境要求**：需要安装什么？系统要求？

## 教程结构模板

### 版本 1：入门教程（Hello World → 真实项目）

**适用场景**：新手首次接触某技术

```markdown
# [技术] 入门教程：从零到 [具体成果]

## 你将学到什么（Learning Objectives）
- [ ] 目标 1
- [ ] 目标 2
- [ ] 目标 3

## 前置要求
- 了解 [X]
- 安装 [Y] (版本 >= Z)

## Step 1: Hello World（5分钟）
[最小可运行示例，建立信心]
### 代码
### 预期输出
### 发生了什么？（一句话解释）

## Step 2: 核心功能（15分钟）
[在 Step 1 基础上增量添加]
### 代码
### 预期输出
### 原理解释

## Step 3: 真实场景（20分钟）
[完整的实际用例]

## Step 4: 进阶技巧（可选）
[面向有余力的读者]

## 常见问题 FAQ
## 下一步学习路径
## 完整代码（GitHub 链接）
```

→ 参见 `examples/tutorial-beginner.md`

### 版本 2：实战教程（构建完整项目）

**适用场景**：有一定基础的开发者，通过项目学习

```markdown
# 用 [技术栈] 构建 [项目名]（完整教程）

## 最终效果展示（截图/GIF/Demo链接）
## 技术栈一览（表格）
## 项目初始化
## 功能 1: [核心功能]
## 功能 2: [扩展功能]
## 部署上线
## 总结与扩展方向
```

→ 参见 `examples/tutorial-project.md`

## 教程写作核心原则

1. **每个 Step 独立可验证**：做完就能看到效果，不等到最后才能跑
2. **明确时间预期**：让读者知道需要投入多少时间
3. **提供完整代码**：附 GitHub 仓库链接或 CodeSandbox
4. **预判踩坑点**：在读者可能出错的地方提前用 `⚠️ 注意` 提醒
5. **渐进式复杂度**：先能跑 → 再好看 → 再考虑性能
6. **友好的错误信息**：如果某步可能失败，告诉读者怎么排查

## 代码块规范（教程专用）

```
每个代码块必须包含：
1. 语言标注（```javascript）
2. 文件路径注释（// src/App.tsx）
3. 新增/修改的行用注释高亮（// 👈 新增这行）
4. 完整到可直接复制运行
5. 紧跟代码块后给出预期输出
```

## Quality Checklist

- [ ] 每个 Step 是否都有预期输出？
- [ ] 读者是否能在不看其他资料的情况下完成教程？
- [ ] 环境要求和版本号是否明确标注？
- [ ] 踩坑点是否提前标注？
- [ ] 是否提供了完整源码链接？
- [ ] 时间预期是否合理标注？
