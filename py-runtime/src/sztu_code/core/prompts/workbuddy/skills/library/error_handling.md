# 资料库错误处理

**何时读取**：收到 `{"error": ...}` 时读取本文件，按行动表处理。正常调用不读本文件。

## 错误码行动表（唯一权威）

收到 `{"error": ...}` 后提取 `code=<错误码>`，按下表执行；安全 `msg` 只用于补足错误参数、状态和受限对象。脚本和外层包装不得另写下一步；同一错误出现多层包装时，以最内层后端业务码为准，只执行本表的一条动作。错误码只用于模型决策，给用户时转换为自然语言，不展示内部码。

| 错误码 / 条件 | 错误类型 | 模型需结合本次调用补足 | Agent 下一步 | 重试规则 |
|---|---|---|---|---|
| `11007`、`11607`、`56040`、`400` / `HTTP_400`、`413` / `HTTP_413`、`422` / `HTTP_422`、`INVALID_PARAMS`；或无 code 但脚本明确报本地参数校验失败 | 参数错误 | 错误参数；当前模块 `entry.md` / 脚本 `--help` 中的正确格式和正确示例 | 修正参数；无法确定时询问用户 | 修正后最多调用 1 次 |
| 本地 `AUTH_REQUIRED`（当前网络命令前尚未通过 `DeferExecuteTool` 成功取得非空 token） | 客户端鉴权前置未完成 | 检查本轮是否已严格执行 `ToolSearch` → `DeferExecuteTool`，以及返回是否为 `authenticated=true` 且 token 非空 | 尚未执行时按规定补做一次；工具不可用或换票失败则停止，不向用户误报为资料权限不足，也不搜索其它凭证来源 | 正确换票最多 1 次 |
| `12100`、`12607`、`56030`、`401` / `HTTP_401`、`403` / `HTTP_403`，或已经成功换票并注入非空 token 后后端仍返回 `AUTH_REQUIRED`（permission 模块明确表示能力关闭时除外） | 权限不足 | 当前角色（已知则写实际角色，否则写“未登录或角色未知”）；缺少的权限；本次 nodeId/spaceId 等受限对象 | 直接告知用户 | 不重试 |
| `11510`、`404` / `HTTP_404`、`410` / `HTTP_410` | 资源不存在 | 本次 nodeId 与路径状态；旧路径标记为失效 | 有 nodeId 时用 `space.workspace.node-info` 按 ID 重解析 1 次；没有时从有效链接重新解析 | 不重复按旧路径调用 |
| `11112`、`19901`、`56039`、`409` / `HTTP_409`、`423` / `HTTP_423` | 状态或版本冲突 | 当前状态；对应模块的最新版读取方式 | 拉最新版并按 `mutation.md` 重建变更；团队目标此前确认失效，旧 transaction 一律失效 | 不复用旧事务；团队目标不复用旧确认 |
| `18406`、`56029`、`501` / `HTTP_501`、`CAPABILITY_DISABLED`；permission 模块因 apply/invite 开关返回的 `403` / `HTTP_403` | 能力未开放 | 当前关闭的能力；当前模块已开放的替代方案 | 直接说明能力未开放和替代方案 | 不重试 |
| `619610` / `11511`（内容安全）、`56031`（个人账号访问企业网盘）、`56032`（企业账号访问个人网盘）、`56033`（跨企业）、`56034`（仅空间 owner）、`56035`–`56037`（该空间操作受限）、`56041`（信安处置） | 受保护资源 | 命中的括号内保护规则与受限对象 | 直接说明保护限制 | 不重试 |
| `429` / `HTTP_429` | 速率限制 | 建议停止连续调用并稍后操作 | 停止当前连续调用 | 不立即重试 |
| `50000`、`56038`、`500` / `HTTP_500`、`502` / `HTTP_502`、`503` / `HTTP_503`、`504` / `HTTP_504`、`NETWORK_ERROR`、`TEMPORARY_ERROR`、`INVALID_RESPONSE`、`UNKNOWN` | 临时故障 | mutation 是否可能已成功；对应只读状态查询方法 | 先查状态；确认未生效后才可重新提交 | 禁止无状态检查的重复 mutation |

未列出的后端业务码，以及无 code 且不属于明确本地参数校验的错误，均按临时故障处理；可引用安全 `msg` 说明现象，但不得据此覆盖本表重试规则。先查状态，再决定是否需要用户介入。
