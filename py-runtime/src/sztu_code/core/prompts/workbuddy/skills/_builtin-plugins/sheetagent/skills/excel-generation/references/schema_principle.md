# 建表设计准则 (schema_principle.md)

> 本文件是主代理**编写 openpyxl 建表脚本**时的强约束清单。目标不是枚举所有行业模板，而是让主代理用少量通用原则推断任意用户场景，产出可用、清晰、可维护的 Excel。**准则作为写代码时的设计知识读入上下文，直接指导代码，不产出 schema.md 中间文档。**
> 如果用户明确要求与本准则冲突，以用户要求为准，但仍应尽量保持可编辑、可计算、可阅读。

---

## 0. 设计目标

生成的 workbook 应：**能直接用、结构清楚、公式联动、视觉克制、便于维护、不过度设计**——各项具体规则见后续各节与 §11 禁止事项。

---

## 1. 场景原型识别

主代理写建表代码前，必须先判断用户需求命中的一个或多个**场景原型**。不要按行业硬套模板，要按工作方式组合原型。

| 原型 | 用户信号 | 默认设计方向 | 范式文件 |
|---|---|---|---|
| 记录型 | 记录、清单、台账、明细、登记、列表、管理 | 单个明细表优先，字段规范、筛选、冻结表头 | —（用通用准则） |
| 计划型 | 计划、安排、排期、里程碑、周期、负责人、交付 | 事项/任务 + 时间 + 负责人 + 状态 + 备注 | `plan.md` |
| 打卡/进度型 | 打卡、完成、进度、学习、习惯、训练、检查项 | 状态列、周期列、完成统计、进度百分比 | `progress.md` |
| 统计型 | 统计、汇总、分析、报表、排名、占比、趋势 | 明细 + 汇总，汇总引用明细，必要时加图表 | `stats.md` |
| 表单/打印型 | 打印、签字、提交、填报、申请、考勤、登记表 | 标题区、填写区、签字栏、稳定版式、打印设置；长文本数据行避免统一固定行高 | `form_print.md` |
| 看板型 | 看板、一眼看、概览、KPI、仪表盘、领导汇报 | KPI 区 + 图表区 + 支撑明细，信息密度适中 | `dashboard.md` |
| 日历/排程型 | 日历、月历、周计划、日程、排班、日期格 | 日期视图 + 事项清单，必要时按月/周拆分 | `calendar.md` |
| 计算模型型 | 预算、资产、收益、成本、库存、收支、测算 | 输入假设 + 计算区 + 结果区，公式必须可追踪 | `model.md` |

> Step 3 据本表末列直接 Read 命中原型的范式文件（design_patterns/ 下）；标"—"的直接用通用准则。

### 1.1 原型组合规则

- 一个需求可命中多个原型。例如"项目预算跟踪表" = 计划型 + 统计型 + 计算模型型。
- 组合时按用户**核心交付目标**定**主原型**（以其范式为骨架），其余作补充、融合次原型的区块/字段；命中多个就读多个范式再融合，未命中任何原型则回退通用准则。
- 命中统计型或看板型时，通常需要 `明细` + `汇总` 或 `看板` + `明细`。
- 命中表单/打印型时，可以使用合并标题、签字栏和固定版式；其他原型默认少用合并单元格。
- 用户只说"做个表/模板"且无其他线索时，默认按记录型轻量模板处理，不主动复杂化。

## 2. 结构决策

### 2.1 Sheet 拆分原则

| 条件 | 策略 |
|---|---|
| 逻辑单一、字段少、数据量 ≤ 50 行 | 单 sheet |
| 用户需要持续录入明细 | 建 `明细` 或业务名明细表 |
| 存在汇总、统计、看板、图表 | 至少拆为 `汇总/看板` + `明细` |
| 存在明显周期维度（月/周/季度）且每期版式相同 | 可按周期拆 sheet，或单 sheet 加周期字段；日历/排程型可按月拆 |
| 存在输入假设与计算结果 | 拆为 `输入` + `计算/明细` + `结果/汇总`，简单场景可放同一 sheet 的不同区域 |
| 用户明确指定 sheet 结构 | 严格遵循用户要求 |

- 单个 workbook 默认 sheet 数量 ≤ 10；超过时优先合并维度或询问是否需要拆文件。
- Sheet 名 ≤ 31 字符，使用简短中文或英文，禁止 `\ / * ? [ ] :`。
- 本生成链路用逗号传递 sheet 名，Sheet 名还应避免英文逗号 `,`。
- Sheet 顺序默认为：`看板/汇总` 在前，`明细/输入` 在后，`配置/说明` 最后。

### 2.2 区域模块

建表时应按需要组合以下模块，而不是死套行业模板：

| 模块 | 用途 | 样式与行为 |
|---|---|---|
| 标题区 | 标明 workbook/sheet 主题 | 可合并居中；普通数据表只在首行使用 |
| 输入区 | 用户填写原始数据或假设 | 浅色底；避免公式；必要时数据验证 |
| 明细区 | 存放可筛选、可追溯的行级数据 | 表头固定，数据从下一行开始，少合并 |
| 计算区 | 放公式派生字段或中间计算 | 中性色或浅灰底；备注写清公式逻辑 |
| 汇总区 | 合计、平均、占比、达成率、余额等 | 强调色或加粗；必须引用明细/输入 |
| 状态区 | 完成、逾期、风险、异常、优先级 | 枚举 + 条件格式 |
| 时间区 | 日期、月份、周次、阶段、日历格 | 日期格式统一，可按周期分组 |
| 备注区 | 长文本、说明、下一步动作 | 宽列，自动换行，左对齐 |
| 打印区 | 部门、负责人、签字、填报日期 | 仅表单/打印型默认启用 |

### 2.3 表头与数据区

- 明细表表头默认在第 1 行；如有标题区，表头可在第 2 或第 3 行，写代码时按此真实行号落公式。
- 每列必须有表头，禁止数据列中间穿插空列。
- 数据从表头下一行开始，普通数据表禁止用空行做分组分隔。
- 如需汇总行，放在数据区最下方，或单独放汇总区；写公式前先确定其真实行号。
- **坐标锚点优先原则（写公式前必做）**：
  - **先定锚点再写公式**：动笔前先在心里确定该 sheet 的布局锚点——标题行、表头行、数据起止行、合计行、KPI 卡片位置、网格 / 合并范围。openpyxl 里所有公式坐标、填充范围、条件格式范围、图表数据源都必须由这些真实锚点推导。
  - **公式坐标是唯一真相**：写进 `ws['B3'] = '=...'` 的坐标就是权威，必须与真实布局一致；不存在"另一处再声明一套坐标"的问题——代码即坐标。
  - **样式/条件格式/打印范围引用真实数据区**：这些执行范围按既定锚点写，不自造第二套坐标；需要取得实际数据结束行时，使用数据集合长度或既定锚点，不得在铺设样式或公式后用 `ws.max_row` / `calculate_dimension()` 反推。若已按 §5.3 明确生成预留录入行，则基础样式、数据验证、适用的条件格式、筛选、汇总引用和带空值保护的计算列公式使用既定预留终点；预留终点仍须预先确定，不从工作表已使用范围反推。
- **哪些表要格外当心锚点（复杂表判定）**：满足任一即属复杂表，动笔前务必先把锚点定清楚——①有标题行 / 表头不在第 1 行；②同一 sheet 有多个区块 / 分区；③二维版式（同一 sheet 内既按行又按列划分区块，如 KPI 卡片矩阵、日历网格、打卡矩阵）；④合计行**且**叠加了 ①~③ 中任一。**降噪例外**：单区块明细表仅在数据区末尾加一行合计（无标题行、无多区块），锚点简单，按"表头第 1 行、数据第 2 行起"即可。
- 写计算列公式坐标前，必须先确定行号锚点：复杂表先定标题/表头/数据/合计的真实行，简单表按"表头第 1 行、数据第 2 行起"定；坐标一律由锚点推导，不得先写默认第 2 行公式再改布局。例如布局为"第 1 行标题、第 2 行表头、第 3~5 行数据、第 6 行合计"时，计算列公式应写 `B3`、`B3:B5`、`B6`，不能写 `B2:B4`。

## 3. 字段设计

### 3.1 类型系统

字段的"类型"必须描述单元格最终值 / 显示格式，写代码时映射到 openpyxl `number_format`，使用以下标准类型之一：

| 类型 | 含义 | openpyxl 落地格式 |
|---|---|---|
| `文本` | 纯文字 | 左对齐 |
| `数字` | 整数或小数 | 右对齐，千位分隔符 |
| `数字（N位小数）` | 指定精度 | 右对齐，`0.00` 等 |
| `货币（¥）` / `货币（$）` | 金额 | 右对齐，`¥#,##0.00` 或 `$#,##0.00` |
| `百分比` | 小数比例显示为百分比（如 `0.85`=85%） | 右对齐，`0.00%` |
| `日期` | 日期 | `YYYY-MM-DD` |
| `日期时间` | 日期+时间 | `YYYY-MM-DD HH:mm` |
| `布尔` | 是/否、完成/未完成 | 居中；可用 `是/否`、`✓/✗` 或 `☑/☐` |
| `枚举` | 有限选项集 | 备注列列出全部选项 |
| `序号` | 自增行号 | 居中，纯整数 |

不得新增临时类型。单位不要写进类型，应写在字段名或备注中，例如 `销售额（万元）` + `数字（2位小数）`。

**值类型落地**：写常量、输入值和样例数据时，字面值按字段类型写成对应 Python 原生类型并设 `number_format`（**计算列不适用——按下文写 Excel 公式字符串**）：`日期` / `日期时间` 用 `date` / `datetime` 对象，`数字` / `货币` 用 `int` / `float`，`百分比` 用小数比例 `float`（如 `0.85`=85%，可超 100% 或为负），`序号` 用 `int`；`文本` / `枚举` 等写 `str`（**即使作为 `SUMIFS` / `COUNTIFS` 的匹配条件也仍是文本**）。避免把日期、数值写成字符串导致计算类公式无法求值。

字段的"来源"描述字段值从哪里来，也可描述字段值如何生成，例如 `用户填写`、`用户原话`、`推断`、`reference/<stem>/content.md`、`计算列`。

`计算列` 是字段的**生成方式**，不是显示类型。写代码时：

- 如果字段由公式派生，把它当"来源=计算列"处理。
- "类型"仍是最终显示格式，例如 `百分比`、`货币（¥）`、`数字（2位小数）`、`日期`。
- **公式直接写进 openpyxl 公式字符串**（如 `ws['H2'] = '=...'`）：写完整公式、引用的字段/列、适用范围或填充方式、必要的空值 / 除零保护；坐标匹配字段所在 sheet / 区块的真实布局。
- 公式坐标必须匹配真实布局（复杂表按 §2.3 锚点优先原则先定锚点）；即便是简单表（含数据区末尾单行合计），也必须按真实行写具体单元格和范围，例如 `B3`、`B3:B6`、`B7`，不得默认数据从第 2 行开始。
- 涉及除法 / 比率的计算列，其分母空值与 0 值保护、分子为空返回空白等规则统一见 §4.1；**写公式字符串时就带上完整保护**，不能只在注释里写"除零保护"。

### 3.2 列排布原则

- 默认顺序：**标识列**（序号、ID、名称）→ **时间列** → **维度列**（分类、区域、负责人）→ **状态列** → **度量列**（金额、数量、百分比）→ **计算列** → **备注列**。
- 强相关字段相邻放置，如 `单价`、`数量`、`小计`；`开始日期`、`结束日期`、`持续天数`。
- 字段名 ≤ 10 字为佳；单位可放字段名括号中，如 `金额（元）`。
- 单 sheet 列数 ≤ 26 为佳；超过时考虑拆 sheet、拆模块或精简字段。
- 备注、说明、行动项等长文本列放最后，设置较宽列宽和自动换行。

### 3.3 常见字段推断

| 原型 | 建议字段 |
|---|---|
| 记录型 | 序号、日期、类别、对象/名称、数量/金额、负责人、状态、备注（可按业务语义增补专属字段，如联系人、到期日、资产编号） |
| 计划型 | 序号、任务、负责人、开始日期、结束日期、阶段、优先级、状态、交付物、备注 |
| 打卡/进度型 | 序号、项目、周期/日期、目标次数、完成状态、完成次数、完成率、备注 |
| 统计型 | 维度字段、指标字段、目标值、实际值、差异、达成率、排名/占比 |
| 表单/打印型 | 填报单位、填报人、日期、明细项、签字确认、备注 |
| 看板型 | 指标名称、本期值、目标值、差异、趋势、状态、说明 |
| 日历/排程型 | 日期、星期、事项、开始时间、结束时间、负责人、进度、备注 |
| 计算模型型 | 输入假设、数量、单价、金额、税率/费率、合计、差异、结果 |

## 4. 公式联动

### 4.1 基本原则

- 能由其他字段推导的值，一律作为**计算列**用公式生成，不要写死。
- 汇总 sheet 的指标必须引用明细 sheet 或输入区，不要孤立手填。
- 模板类表格的公式应能在用户后续填入数据后自动更新。
- 计算列的公式直接写进 openpyxl 公式字符串（`ws['H2'] = '=...'`），公式坐标即唯一真相，不存在第二处声明。
- 公式坐标必须按真实布局写、适用范围和填充方式清楚：普通明细表可写 `H2`、`H2:H25`，多区块 / 汇总表先按 §2.3 锚点优先原则定锚点再按该区块实际坐标写，不能套用默认第 2 行。
- 简单聚合优先用 Excel 原生公式，如 `SUM`、`AVERAGE`、`COUNTIF`、`SUMIF`、`COUNTIFS`。
- 公式要按运算类型处理空值和除零：加减法、差异、余额等公式只需要保护必要空值，不应把合法的 0 值当作空白；涉及除法、排名、达成率、同比、占比时，**公式字符串本身必须显式包含分母空值和 0 值保护**（如 `OR(E2="",E2=0)` 或语义等价的 `IFERROR`），且比率公式分子为空时也应返回空白——不得只在注释里写"除零保护"。生成后用 recalc（或降级静态检查）读回验证公式文本。

### 4.2 必须优先公式化的字段

| 字段/场景 | 公式逻辑 |
|---|---|
| 小计/金额 | `单价 × 数量` |
| 合计/总计 | 对明细金额或数量求和 |
| 差异/偏差 | `实际值 - 目标值` 或 `本期 - 上期` |
| 达成率/完成率 | `实际值 / 目标值` 或 `完成数 / 总数` |
| 同比/环比 | `本期 / 对比期 - 1` |
| 余额 | `期初 + 收入 - 支出` |
| 出勤/完成次数 | 对 `√`、`☑`、`已完成` 等状态计数 |
| 持续天数 | `结束日期 - 开始日期 + 1` |
| 星期/月/周 | 由日期自动推导 |
| 热量/预算/库存收支 | `收入/摄入/入库 - 支出/消耗/出库` |

### 4.3 公式与样例数据

- 如果生成样例数据，样例数据必须与公式结果自洽。
- 如果用户要空模板，保留公式列，但公式应在输入为空时显示空白或 0，不显示错误值。

### 4.4 汇总表坐标示例（复杂表：先定锚点，再按锚点写 openpyxl 公式）

有标题行的汇总 sheet 属复杂表：动笔前先定行号锚点（第 1 行标题、第 2 行表头、第 3~5 行数据、第 6 行合计），再按锚点写 openpyxl 公式，除零保护直接写进公式字符串。示例：

```python
# 锚点：第1行标题、第2行表头、第3~5行数据（每行一个渠道）、第6行合计
ws["A1"] = "渠道销售汇总"          # 标题行（合并居中见样式）
# 表头行
for col, name in zip("ABCF", ["渠道", "目标销售额(万元)", "实际销售额(万元)", "平均达成率"]):
    ws[f"{col}2"] = name
# 数据区 A3:A5 + 计算列（引用明细 sheet）
for i, ch in enumerate(["直营", "经销", "线上"]):
    r = 3 + i
    ws[f"A{r}"] = ch
    ws[f"B{r}"] = f"=SUMIF(明细!B:B,A{r},明细!D:D)"
    ws[f"C{r}"] = f"=SUMIF(明细!B:B,A{r},明细!E:E)"
    ws[f"F{r}"] = f'=IF(OR(B{r}="",B{r}=0),"",C{r}/B{r})'   # 达成率：分母空/0 保护
# 合计行（第6行）
ws["A6"] = "合计"
ws["B6"] = "=SUM(B3:B5)"
ws["C6"] = "=SUM(C3:C5)"
ws["F6"] = '=IF(OR(B6="",B6=0),"",C6/B6)'
```

错误写法：数据区明明从第 3 行起，却写 `ws["B2"] = "=SUMIF(...)"；填充 B2:B4`——坐标没按锚点推导。

## 5. 数据与样例策略

### 5.1 样例数据规模

| 用户意图 | 样例数据规模 |
|---|---|
| 明确说要 N 行数据 | `N 行` |
| 说"模板/给我填/空表" | `0 行（仅表头和公式/验证，留空给用户填写）` |
| 说"示例/样例/演示" | `5~10 行合理样例` |
| 没说清楚 | `5 行样例数据`，除非更像空模板 |
| 有附件且附件含真实数据 | `按 reference/<stem>/content.md 实际数据量` |
| 表单/打印型 | 按一页可打印容量设计，不为凑数据硬造大量行 |

### 5.2 样例数据质量

- 数据必须逻辑自洽，公式结果能对上。
- 数字分布要真实，不要全是整十整百。
- 日期要连续或符合业务周期；涉及工作日/自然月时要合理。
- 枚举值至少覆盖主要选项一次。
- 中文场景用中文样例数据；英文用户需求可用英文。
- 不主动造敏感个人信息、真实公司名、证件号、手机号等。
- 附件来源的数据不确定就不强行造，按 `reference/<stem>/content.md` 核对；图片 / 扫描内容先看 `thumbnails/` 辅判。

### 5.3 空值处理

- 不主动造空值，除非场景合理，如备注列可空。
- 附件或用户原始数据有空值时，在代码里明确处理策略：留空、填 `N/A`、填 0 或排除统计。
- 仅当用户明确要求“空表 / 模板 / 给我填 / 持续录入 / 预留 N 行 / 预留录入区”时，才生成预留录入行；“登记 / 记录 / 追踪 / 计划”等场景名称本身不构成预留依据。用户明确指定预留 N 行时按 N 行处理；明确要求预留但未指定数量时，默认预留 5 个空白录入行（不包含实际数据或样例数据），不得自行扩大；表单 / 打印型仍按 §5.1 的一页容量设计。已经确定需要预留时，预留行应按列继承适用的基础样式、数字格式和数据验证，适用的条件格式、筛选及汇总引用应覆盖同一预留范围；输入列保持空白，计算列预填与数据行逻辑相同且带空值保护的公式，序号等自动列也应在关键输入为空时显示空白。不得复制由具体数据值触发的静态状态样式。用户填入后，显示、计算和交互行为应与上方数据行一致。

## 6. 样式层级

### 6.1 样式总原则

- 同一 sheet 建议使用 1 个主色 + 1 个浅底色 + 必要警示色。
- 标题、表头、输入区、计算区、汇总区、状态区必须能视觉区分。
- 不使用大面积高饱和背景色；深色只用于标题/表头/关键汇总。
- 有真实数据的普通表格优先保证筛选和阅读，不为了美观破坏数据结构。
- 样式 / 条件格式在代码里必须落到具体值（颜色码、格式串），不停在"美观一点"这种模糊描述。

### 6.2 预设配色方案

| 风格 | 适用场景 | 表头背景 | 表头字色 | 输入/浅底 | 汇总/强调 |
|---|---|---|---|---|---|
| 商务蓝（默认） | 正式报告、经营分析、汇报 | `#4472C4` | `#FFFFFF` | `#D9E2F3` | `#2F5597` + 白字 |
| 轻量灰 | 自用、极简、数据清单 | `#F2F2F2` | `#1A1A1A` | `#FAFAFA` | `#E0E0E0` |
| 清新绿 | 项目、任务、进度、打卡 | `#70AD47` | `#FFFFFF` | `#E2EFDA` | `#548235` + 白字 |
| 日历多彩 | 日历、计划、年度目标 | 每个周期一个主色 | `#FFFFFF` | 主色 10%~20% 浅底 | 主色深一档 |
| 打印黑白 | 打印、签字、填报 | `#FFFFFF` | `#000000` | `#FFFFFF` | 粗边框/加粗，不依赖颜色 |
| 用户指定 | 用户明确提及颜色/风格 | 按用户要求 | 按用户要求 | 按用户要求 | 按用户要求 |

选择规则：

- 用户未提及风格，默认商务蓝。
- 用户说"简洁/简单/轻量/自用/极简"，用轻量灰。
- 用户说"项目/任务/进度/打卡/看板"，优先清新绿。
- 用户说"日历/月历/年度计划/排程"，可用日历多彩，但每个 sheet 内仍保持克制。
- 用户说"打印/签字/表单/考勤/登记"，优先打印黑白。
- 用户给出具体颜色，按用户指定。

### 6.3 表头、输入区、计算区

- 表头：加粗、水平居中、下边框 `thin`，按配色方案设置背景和字色。
- 输入区：浅底色，普通字体，明确留给用户填写。
- 计算区：浅灰或浅黄底，备注说明公式，不应让用户手填覆盖。
- 汇总区：加粗，上边框 `thin`，必要时深色背景 + 白字。
- 布尔/打卡列：居中，可用 `☐/☑` 或 `是/否`。
- 长文本列：左对齐、自动换行（wrapText）、列宽按 §8.1 策略设置。

### 6.4 合并单元格

- 普通数据表、明细表默认不合并单元格，避免影响筛选、排序和复制。
- 允许合并的场景：标题区、打印表单抬头、签字栏、日历月标题、项目计划中的视觉分组。
- 使用合并单元格仅用于版式需要（标题、抬头、签字栏等）；不要把合并用于普通数据分组。

## 7. 条件格式与高亮

### 7.1 触发条件

满足以下任一条件时，应加入条件格式（openpyxl `conditional_formatting`）：

- 用户明确说"标红/高亮/预警/醒目/一眼看出"。
- 有状态列，如 `已完成/进行中/逾期/风险`。
- 有阈值判断，如达成率、预算执行率、库存下限、热量超支。
- 有日期逾期或临近截止日期。
- 有负数、亏损、异常值。

### 7.2 写法规范

必须写清三要素：**应用范围 + 条件 + 样式**。

示例：

```markdown
条件格式：
- 达成率列：>=100% → 绿底(#C6EFCE)+绿字(#006100)；<80% → 红底(#FFC7CE)+红字(#9C0006)
- 状态列："已完成"→ 绿底(#C6EFCE)；"逾期"→ 红底(#FFC7CE)；"进行中"→ 黄底(#FFEB9C)
- 截止日期列：日期 < 今天且状态 != "已完成" → 红字(#9C0006)
```

### 7.3 常用规则

| 场景 | 条件 | 样式 |
|---|---|---|
| 达标/超标 | 数值 >= 目标 | 绿底 `#C6EFCE` + 绿字 `#006100` |
| 低于预警线 | 数值 < 阈值 | 红底 `#FFC7CE` + 红字 `#9C0006` |
| 接近预警 | 阈值附近 | 黄底 `#FFEB9C` + 深黄字 `#9C6500` |
| 状态完成 | = "已完成" 或 `☑` | 绿底或绿字 |
| 状态逾期/风险 | = "逾期"/"高风险" | 红底或红字 |
| 日期逾期 | 日期 < 今天 | 红字 `#9C0006` |
| 负值/亏损 | 数值 < 0 | 红字 `#9C0006` |

不触发条件格式的场景：

- 纯空模板且没有状态/阈值。
- 用户只是要简单记录表，没有好坏判断。
- 用户明确说不要颜色或不要高亮。

## 8. 可用性规则

### 8.1 冻结、筛选、列宽

- 明细数据 ≥ 10 行，默认开启筛选。
- 明细数据 ≥ 20 行，默认冻结表头；有序号/ID/名称列且横向较宽时，同时冻结首列。
- 日期、金额、百分比必须使用统一格式。
- 表头和关键数字不得被截断。

**列宽策略**：

> 写代码时用 `ws.column_dimensions['X'].width = N` 直接设列宽。标准类型列按内容给合理宽度，长文本/备注类列给较大宽度并开启 wrapText。

**① 需要显式给较大宽度 + wrapText 的列（长文本类）：**

| 列类型 | 建议宽度 | 说明 |
|---|---|---|
| 长文本（任务描述、说明） | 约 28~36（openpyxl width 单位） | 搭配 wrapText，单行约 12~16 汉字 |
| 备注/行动项 | 约 34~50 | 搭配 wrapText，宽表可更大 |
| 地址/长路径 | 约 36~50 | 搭配 wrapText |

> 若某列字段名或语义暗示会承载自由文本、多句描述、URL、文件路径、详细说明、处理意见、跟进记录等内容，倾向于按宽列设置列宽和自动换行。

**② 标准类型列按内容给合理宽度即可：**

序号、姓名、日期、枚举、状态、金额、百分比、手机号、邮箱、电话等——按表头文字长度与数据内容宽度选合理宽度，不必刻意加宽。

**③ 硬约束：**

- 长文本、备注类列**必须同时开启自动换行（wrapText）**。
- 表头和关键数字不得被列宽截断。

### 8.2 数据验证

以下场景应设计数据验证或枚举说明：

- 状态列：`未开始/进行中/已完成/逾期/暂停`。
- 优先级列：`高/中/低`。
- 布尔列：`是/否` 或 `☐/☑`。
- 类别、部门、区域、负责人等可枚举字段。

用 openpyxl `DataValidation` 建真实下拉；确实建不了时，至少用单元格批注或表头说明列出全部选项。

### 8.3 打印设置

命中表单/打印型时，用 openpyxl 打印相关属性（`page_setup` / `print_options` 等）加入打印设置：

- 页面方向：列数多时用横向；窄表用纵向。
- 标题居中，可合并；保留部门、填报人、负责人、日期、签字确认等字段。
- 含长文本列并开启自动换行（wrapText）的数据区，不要指定或建议数据行高；只有用户明确要求固定数据行高或每条记录等高时，才可指定数据行高，且必须保证内容不被裁切。
- 尽量一页容纳主表；如果数据多，说明按页延续。
- 打印型可用边框增强结构；颜色不应是唯一的信息载体。

## 9. 图表与看板

### 9.1 何时加图表

满足以下任一条件，且数据适合可视化时，应设计图表：

- 用户说"分析/趋势/对比/汇报/看板/KPI"。
- 存在时间序列、分类对比、占比构成或目标达成。
- 汇总 sheet 中有 3 个以上可比较指标。

用户只是要空模板、登记表、打印表单时，不主动加图表。

### 9.2 图表类型

| 数据特征 | 推荐图表 |
|---|---|
| 时间序列趋势 | 折线图 |
| 分类对比 | 柱状图（≤ 7 类）或条形图（> 7 类） |
| 占比/构成 | 饼图（≤ 5 类）或环形图 |
| 目标 vs 实际 | 组合图或柱状图 |
| 两个度量关系 | 散点图 |
| KPI 概览 | 指标块 + 小型趋势图 |

### 9.3 图表放置

- 默认放在汇总/看板 sheet。
- 简单明细表可把图表放在数据右侧空白区域。
- 图表必须引用表格数据区域（`openpyxl.chart.Reference`），不要孤立造图。
- 用 openpyxl.chart 建图表：明确所在 sheet、图表类型、数据源区域与表达目的。

## 11. 禁止事项

- 不要设计超过用户需求的内容。用户要 3 列模板，不要主动加 10 列和多个 sheet。
- 不要把可由公式推导的值写死（除非用户只要静态展示）；能由公式推导的一律写公式。
- 不要滥用合并单元格；普通明细表和需要筛选的数据表尤其禁止。
- 不要使用过多颜色；同一 sheet 中主色、浅底、警示色之外不要继续扩展。
- 不要让单个 sheet 超过 1000 行样例数据；如需大量数据，用循环/批量方式在脚本里生成。
- 不要在空模板中显示公式错误值，如 `#DIV/0!`、`#VALUE!`、`#REF!`。
- 不要用真实敏感信息做样例数据。
