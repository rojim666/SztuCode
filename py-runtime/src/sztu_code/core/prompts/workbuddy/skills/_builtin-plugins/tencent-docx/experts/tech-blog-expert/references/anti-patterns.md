# 技术博客反模式清单

> 看到这些信号就要避免——它们是经过验证的"坑"

## 致命反模式（必须避免）

### 1. 文档翻译体
```
❌ 把官方文档翻成中文，一字不差
✅ 用自己的理解重新组织 + 加入实践经验
```
**问题**：零价值，读者直接看文档更准确
**诊断信号**：行文结构与官方文档高度一致，无个人经验

### 2. 代码片段陷阱
```
❌ 只贴关键3行代码，省略上下文
✅ 完整可运行的代码块 + 关键行注释
```
**问题**：读者无法运行，体验极差
**诊断信号**：代码块中出现 `...` 或 `// 省略` 且无完整示例链接

### 3. 版本盲
```
❌ "安装 React Router"（不说版本）
✅ "安装 React Router v6（本文基于 v6.20+，v5 语法不同）"
```
**问题**：读者按文章操作全报错
**诊断信号**：全文无版本号或版本号与示例代码不匹配

### 4. 概念错误
```
❌ "React 的虚拟 DOM 比真实 DOM 更快"
✅ "虚拟 DOM 的价值是批量更新和跨平台抽象，不一定比直接操作 DOM 快"
```
**问题**：传播错误知识
**诊断信号**：对技术概念做绝对化描述

### 5. 标题党
```
❌ "震惊！这个 API 让性能提升 1000 倍"
✅ "使用 Web Workers 将大数据处理性能提升 3-5 倍（附 Benchmark）"
```
**问题**：失去读者信任
**诊断信号**：标题含"震惊/颠覆/秒杀/吊打"等词汇

## 严重反模式（应当避免）

### 6. 炫技型
```
❌ 堆砌 5 个高深概念不解释
✅ 每个概念首次出现时给一句话解释
```
**问题**：读者看不懂，关掉页面
**诊断信号**：首次使用专业术语不做解释

### 7. 无图型
```
❌ 纯文字讲微服务架构
✅ 至少一张架构图 + 一张请求链路图
```
**问题**：理解成本极高
**诊断信号**：讲架构/流程时全文无图

### 8. 过时不标注
```
❌ 2年前写的 Webpack 4 教程，不加任何说明
✅ 文章顶部标注 "⚠️ 本文基于 Webpack 4，Webpack 5 部分 API 已变更"
```
**问题**：误导新读者
**诊断信号**：发布日期>1年且涉及快速迭代技术

### 9. 缺少 TL;DR
```
❌ 3000字文章开头就进入细节
✅ 前3行给出核心结论，让忙的读者快速决定是否继续读
```
**问题**：读者不知道这篇文章要讲什么
**诊断信号**：文章>1500字但没有 TL;DR / 概括 / 摘要

### 10. 自嗨式分享
```
❌ "我研究了3个月终于搞懂了 Rust"（然后讲了一堆个人心路历程）
✅ "这是我用 Rust 重写 Node.js 服务后，性能和开发效率的真实对比数据"
```
**问题**：读者想要的是知识，不是作者的心路历程
**诊断信号**：大量第一人称叙述但缺乏技术细节
