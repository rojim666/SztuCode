# 文档规范

[返回文档中心](../README.md)

## 目录职责

| 位置 | 内容 |
| --- | --- |
| `README.md` | 项目定位、核心能力和最快启动路径 |
| `docs/README.md` | 文档索引、状态和导航 |
| `docs/getting-started/` | 面向使用者的安装与配置 |
| `docs/development/` | 面向贡献者的开发、测试和文档规则 |
| `docs/reference/` | 现行架构、协议和实现参考 |
| `docs/operations/` | daemon 运维与故障排查 |
| `docs/guides/` | 评估、方法论等专题实践 |
| `docs/archive/` | 已过时但仍有背景价值的历史材料 |
| `docs/assets/` | 文档引用的图片等静态资源 |

`AGENT.md` 和 `CLAUDE.md` 是仓库开发工具约定，不并入普通用户文档。

## 写作原则

- 先写用户目标和预期结果，再写实现细节。
- 示例命令应可以从标明的目录直接运行。
- 不写会迅速过期的测试数量、提交数量或绝对本机路径。
- 配置项、命令、事件和代码路径必须与当前代码一致。
- 明确区分现行规范、推荐指南、自动生成文件和历史材料。
- 涉及危险动作时说明影响范围、恢复方式和前置备份。
- 文档默认使用 UTF-8，中文为主；标识符和协议字段保留代码中的英文。

## 链接

- 仓库内链接使用相对路径。
- 移动文件时同步更新 README、索引、脚本、测试和其他文档引用。
- 每份详细文档顶部提供返回 `docs/README.md` 的链接。
- 外部资料链接到官方或一手来源，避免依赖不稳定的转载。

调整文档位置或链接后，运行本地链接检查：

```bash
npm run docs:links
```

该脚本检查根目录 Markdown 与 `docs/**/*.md` 中的相对链接是否指向存在的路径，发现坏链时按
`文档路径:行号 -> 目标` 输出全部问题并以非零状态退出。它不访问网络，因此不校验外部站点是否在线，
也不校验标题锚点是否存在；外部 URL、邮箱、纯锚点、图片和围栏代码块中的示例链接都会跳过。

## 自动生成文档

`docs/reference/wire-protocol.md` 由 `scripts/gen_protocol_doc.ts` 生成，不手工编辑：

```bash
npm run docs:protocol
```

若生成内容需要改进，应修改模型或生成器，再重新生成。

## 归档规则

当设计方案已实施、被替代或与现行架构冲突时：

1. 移入 `docs/archive/`；
2. 在标题后添加醒目的历史/过时说明；
3. 链接到替代的现行文档；
4. 从主导航中移到“历史资料”；
5. 保留原文用于追踪决策，不悄悄改写成当前事实。

## 文档变更检查表

- [ ] 文档位于正确目录；
- [ ] 标题和导航清晰；
- [ ] 示例命令已根据代码或 `--help` 核对；
- [ ] 相对链接和资源存在；
- [ ] 没有真实 API Key、个人路径或私有数据；
- [ ] 没有把历史材料描述为现行实现；
- [ ] 协议生成检查通过；
- [ ] 根 README 和文档索引已在需要时同步。
