# 安全政策

[返回文档中心](README.md)

SztuCode 可以读取、修改和执行本地代码，因此权限绕过、路径逃逸、命令注入、凭据泄漏和不可信工作区处理都属于高影响安全问题。请负责任地披露，不要先创建公开 Issue 或发布利用细节。

## 支持范围

项目尚处于 `0.x` 快速开发阶段。安全修复优先面向：

- 默认分支的最新提交；
- 最新公开版本；
- 维护者明确标记仍受支持的发布分支。

较旧提交和个人开发分支通常不会单独修复。若问题同样影响最新版本，仍请报告。

## 报告方式

首选使用 GitHub 仓库的 **Security → Report a vulnerability** 私有报告功能：

<https://github.com/rojim666/SztuCode/security/advisories/new>

如果该入口不可用，请通过 GitHub 私下联系维护者 `@rojim666`，只说明需要安全联系方式，不要在公开 Issue、Discussion、群聊或 Pull Request 中披露漏洞细节。

报告应尽量包含：

- 受影响版本、提交和操作系统；
- 漏洞类型及潜在影响；
- 最小复现步骤或概念验证；
- 所需前置条件、权限模式和用户交互；
- 可能受影响的数据或边界；
- 你已经尝试的缓解或修复方案；
- 是否计划在某个日期公开披露。

请删除真实 API Key、访问令牌、个人信息和不属于你的私有代码。需要交换敏感附件时，先与维护者约定安全渠道。

## 重点关注的问题

我们尤其希望收到以下报告：

- Shell、工具参数或 MCP 调用导致的命令注入；
- 绕过工作区根目录、信任状态、只读模式或权限审批；
- `normal`、`plan`、`accept_edits` 模式下的未授权写入或执行；
- 路径遍历、符号链接或大小写差异导致的目录逃逸；
- API Key、Token、环境变量、会话、Trace 或提示词意外泄漏；
- 不可信仓库内容造成提示注入并突破工具权限边界；
- daemon IPC 被未授权客户端控制或窃听；
- Session、变更回退或归档操作造成跨工作区数据访问；
- 依赖供应链、安装脚本或发布产物被篡改；
- 桌面端渲染未受信内容引发脚本执行或本地资源访问。

以下内容通常不作为安全漏洞处理，但可以创建普通 Issue：

- 仅在 `auto` 模式且用户明确批准全部权限后发生的预期操作；
- 只影响已停止支持版本的问题；
- 不包含安全影响的普通崩溃、界面问题或性能问题；
- 没有可利用路径的泛化模型幻觉；
- 单纯缺少某项最佳实践，且不存在现实攻击路径。

## 响应流程

项目由志愿维护者维护，目标响应时间如下：

- 3 个自然日内确认收到报告；
- 7 个自然日内完成初步分级并说明下一步；
- 高危问题优先制定缓解和修复计划；
- 修复发布后，在征得报告者同意的情况下公开致谢。

实际时间可能受复现难度和维护者可用时间影响。若 7 天内没有收到任何回复，可以再次私下提醒。请在维护者确认修复或双方约定披露日期前保持细节非公开。

## 协调披露

维护者会尽量：

1. 复现并确定影响范围；
2. 准备修复和回归测试；
3. 审查相邻攻击路径；
4. 发布修复版本或缓解建议；
5. 通过 GitHub Security Advisory 或发布说明披露。

未经授权，请不要测试不属于你的系统、访问他人数据、持续运行破坏性命令或扩大漏洞影响。项目无法提供法律上的安全研究豁免；研究者应遵守当地法律、学校规定和相关服务条款。

## 用户安全建议

- 在独立分支和可恢复的工作区中运行 Agent；
- 初次打开陌生仓库时使用只读或计划模式；
- 不把 API Key 写入仓库、提示词、Issue、截图或 Trace；
- 执行高风险命令前检查完整参数和目标路径；
- 定期更新 SztuCode 的 Node.js 和 Rust 依赖；使用 artifact Skill 时，也要更新该 Skill 明确要求的隔离 Python 依赖；
- 发现凭据泄漏时立即撤销凭据，再进行清理和报告。
