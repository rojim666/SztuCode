# SztuCode 路线图

[返回文档中心](README.md)

本路线图描述项目当前的产品边界和阶段性目标，不是交付日期承诺。具体工作以 GitHub Issues、里程碑和已合并代码为准；每个版本只有在验收条件满足后才发布。

## 产品方向

SztuCode 的目标是构建一个本地优先、可审计、可扩展的 AI Coding Agent，同时作为真实的软件工程学习与研究项目。产品主线关注可用性、可靠性和安全边界，研究主线关注项目级代码理解、跨语言工具、领域知识和多智能体协作。

核心原则：

- 本地优先：代码和执行权默认留在用户工作区；
- 人在回路：高风险操作必须可见、可审查、可中断；
- 证据驱动：测试、Diff、Trace 和评测结果优先于模型自述；
- 协议稳定：客户端、daemon 和扩展通过明确契约协作；
- 渐进自主：先保证边界和恢复能力，再提高自动化程度；
- 可贡献：架构、任务和验收方式应让新成员能够理解并参与。

## 当前状态

项目已经具备 Agent Loop、CLI/TUI/桌面客户端、工作区工具、权限审批、会话与记忆、上下文压缩、Skills、Subagents、MCP、Trace 和变更审阅等基础能力。

当前主要缺口是：自动化评测基线、项目级语义索引、统一 LSP、更加可靠的命令安全分析、安全扫描闭环、贡献治理和正式发布流程。

## Contributor Ready

目标：让新成员能够在 30 分钟内理解项目、运行检查并提交第一个小型 PR。

验收条件：

- [ ] 贡献指南、行为准则、安全政策、CODEOWNERS 和 Issue/PR 模板齐全；
- [ ] 架构决策记录机制可用，关键新决策开始留档；
- [ ] `good first issue` 与 `help wanted` 任务具有明确边界和验收标准；
- [x] TypeScript 检查、测试和协议文档校验具有可重复命令；
- [ ] 桌面端构建和验证步骤有明确文档；
- [ ] 基础测试不要求贡献者提供真实模型凭据；
- [ ] 仓库明确学生社区属性，不冒用学校或学院官方身份。

## v0.1：可靠的本地 Agent 闭环

目标：形成可稳定演示和持续评测的本地开发闭环。

重点范围：

- 统一的自动化评测入口、内部任务集和指标报告；
- 工作区打开、任务执行、文件修改、测试、Diff 审阅和会话恢复主流程；
- Shell 命令结构化分析与权限策略强化；
- 核心协议、权限、会话和变更管理的回归测试；
- TypeScript daemon、Node CLI、评测 runner 和 Tauri 桌面端的开发检查进入稳定流程；Python 仅作为隔离 artifact helper 的外部工具。
- 错误状态、取消、断连和恢复行为可观察且不会误报成功。

候选 Issues：[#8](https://github.com/rojim666/SztuCode/issues/8)、[#17](https://github.com/rojim666/SztuCode/issues/17)。

发布门槛：

- [ ] 核心测试、静态检查和构建全部通过；
- [ ] 至少 10 个内部真实任务可重复评测；
- [ ] 高风险工具具有明确权限等级和审批路径；
- [ ] 快速开始可由一名新贡献者独立完成；
- [ ] 已知重大数据丢失或权限绕过问题为零。

## v0.2：项目级理解与跨语言工具

目标：从文本搜索升级到任务驱动的项目语义理解，并建立跨语言适配基础。

重点范围：

- 增量式项目符号索引和依赖关系图；
- 分层上下文检索、Token 预算、来源说明和 Trace；
- 统一 LSP 接口，首期支持 Python 与 TypeScript；
- 项目语言、框架和验证策略自动识别；
- 上下文压缩信息保持率评测；
- Multi-SWE-bench 小规模多语言基线。

候选 Issues：[#9](https://github.com/rojim666/SztuCode/issues/9)、[#10](https://github.com/rojim666/SztuCode/issues/10)、[#11](https://github.com/rojim666/SztuCode/issues/11)、[#12](https://github.com/rojim666/SztuCode/issues/12)、[#13](https://github.com/rojim666/SztuCode/issues/13)、[#14](https://github.com/rojim666/SztuCode/issues/14)。

发布门槛：

- [ ] Python 与 TypeScript 跨文件定义和引用查询稳定可用；
- [ ] 索引可增量更新，并在失败时回退到文本搜索；
- [ ] 上下文选择过程可追溯，关键约束压缩后可量化验证；
- [ ] 至少三种语言完成可复现的基准评测。

## v0.3：领域知识、安全与协作

目标：把领域规则、代码安全和角色化协作纳入任务完成条件。

重点范围：

- 项目与行业知识库 RAG，支持版本、隔离和引用溯源；
- 静态分析、密钥检测和依赖漏洞扫描闭环；
- Planner、Coder、Tester、Reviewer 多智能体工作流；
- 角色权限、任务图、预算、取消和质量仲裁；
- 桌面端展示检索来源、安全 Finding 和子任务状态。

候选 Issues：[#15](https://github.com/rojim666/SztuCode/issues/15)、[#16](https://github.com/rojim666/SztuCode/issues/16)、[#18](https://github.com/rojim666/SztuCode/issues/18)。

发布门槛：

- [ ] 高危安全 Finding 未处置时任务不能宣告成功；
- [ ] 知识检索结果具有可核查来源和隔离边界；
- [ ] 多智能体交接、失败和审批记录完整进入 Trace；
- [ ] 多智能体方案在代表性任务上优于或补充单 Agent 基线。

## v1.0：可维护的公开版本

目标：提供有稳定升级路径、文档和安全响应流程的公开版本。

预期条件：

- 核心 IPC、配置、会话数据和扩展接口具有兼容性政策；
- 安装、升级、迁移、备份和故障恢复文档完整；
- 支持至少一个稳定桌面发行目标和一个命令行发行目标；
- 建立版本发布、变更日志、漏洞响应和弃用流程；
- 关键工作流具有持续评测和回归门禁；
- 社区至少有两名能够独立 Review 核心模块的维护者。

## 研究轨道

以下工作可以并行探索，但只有经过固定评测和安全审查后才能进入默认产品路径：

- 基于执行轨迹和人工反馈的受控优化数据集；
- 测试时计算和多候选方案仲裁；
- 长期记忆质量与遗忘机制；
- 领域专用代码模型或后训练实验；
- 多智能体任务分解、协商和动态调度。

对应研究 Issue：[#19](https://github.com/rojim666/SztuCode/issues/19)。

## 当前非目标

以下内容不属于近期承诺：

- 从零训练通用基础大模型；
- 未经人工审核的线上持续学习或自动修改生产策略；
- 默认将私有代码、Trace 或凭据上传到公共云服务；
- 绕过用户审批或操作系统权限边界的全自动执行；
- 同时支持所有编程语言、IDE、模型供应商和部署平台；
- 代替专业安全审计、合规认证或法律意见；
- 在未经授权的情况下代表学校、学院或社团官方立场；
- 为追求功能数量而复制成熟 IDE 已经稳定提供的通用能力。

## 路线图治理

新增或调整版本目标时，应通过 Issue 或 ADR 说明用户价值、依赖、风险、验收指标和被放弃的方案。路线图每个发布周期至少复查一次；尚无负责人、评测方式或资源条件的项目保留在研究轨道，不进入版本承诺。
