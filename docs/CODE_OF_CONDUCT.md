# 社区行为准则

[返回文档中心](README.md)

## 我们的承诺

SztuCode 是面向学习、研究和产品实践的开放协作项目。我们承诺为所有参与者提供友好、安全、尊重且不受骚扰的环境，不因年龄、经验、身体条件、民族、性别认同与表达、教育背景、国籍、外貌、宗教、性取向、社会经济状况或技术选择而区别对待。

项目重视学习过程，也坚持工程质量。指出问题、要求证据和拒绝不安全的改动是正常协作行为，但反馈必须针对代码、设计和可观察行为，不针对个人能力或身份。

## 鼓励的行为

- 清楚说明事实、假设、风险和不确定性；
- 对新贡献者提供可执行的上下文和耐心指导；
- 尊重不同经验水平，允许提问和承认错误；
- 对代码和技术观点提出具体、可验证的反馈；
- 主动披露利益冲突、生成式 AI 使用和引用来源；
- 保护他人的隐私、凭据、未公开代码和研究数据；
- 接受维护者为项目整体利益作出的范围和优先级决定；
- 在造成影响后及时修正，并总结可以防止复发的流程改进。

## 不可接受的行为

- 侮辱、歧视、威胁、骚扰、跟踪或不受欢迎的性关注；
- 人身攻击、公开羞辱、恶意揣测动机或煽动围攻；
- 未经许可发布他人的个人信息、联系方式、聊天记录或私有代码；
- 提交密钥、Token、恶意代码、后门，或故意绕过权限和安全检查；
- 冒充维护者、学校、学院、社团或其他组织作出官方表态；
- 虚报贡献、抄袭代码或文档，或者隐瞒许可证和来源限制；
- 反复制造噪声、劫持讨论、无视明确边界或干扰项目正常协作；
- 对提出安全问题、行为问题或善意反馈的人进行报复。

## 适用范围

本准则适用于 GitHub 仓库、Issue、Pull Request、代码审查、项目群、社团活动、线上会议、线下讨论以及代表 SztuCode 参与的公开场合。

个人观点不得以 SztuCode、学校、学院或社团官方观点名义发布，除非获得明确授权。

## 报告问题

发现违反行为准则的情况时，请通过 GitHub 向维护者 `@rojim666` 发起私下联系；如果 GitHub 私信不可用，可在仓库创建仅包含“请求维护者私下联系”的 Issue，但不要公开敏感细节。涉及可利用安全漏洞时，必须改按 [SECURITY.md](SECURITY.md) 报告。

报告尽量包含：

- 事件发生的时间和渠道；
- 相关人员或账号；
- 对话、链接或截图等必要证据；
- 是否存在持续风险或需要立即保护的人员；
- 希望采取的保护措施。

维护者会尽量保护报告者和受影响人员的隐私，只向处理事件所必需的人披露信息。故意捏造的报告也违反本准则；善意但最终无法证实的报告不会因此受到处罚。

## 执行原则

维护者根据行为的性质、影响、持续时间和是否重复发生采取措施，包括：

1. **提醒**：私下说明不当行为和改进要求；
2. **正式警告**：记录边界、期限和再次违反的后果；
3. **临时限制**：限制参与讨论、Review、活动或仓库交互；
4. **永久移除**：移出项目社区，并在必要时向平台或所属组织报告。

处理决定应基于证据并避免利益冲突。被指控者如认为决定存在事实错误，可提交一次书面申诉，由未直接参与原决定的维护者或社团指导人员复核；在复核完成前，必要的临时保护措施仍然有效。
